## Database and credentials

All eight committed Prisma migrations were applied. The baseline contains eight
cities, paused scheduler/settler flags, a binding to the proxy, and markets 0–3
reconciled directly from Arc. There was no local database reset or data dump.

`weatherb_app` is the runtime role with server CRUD policies on the active tables;
it cannot create schema objects or read legacy `BotWallet` records. The separate
`weatherb_migrator` owns migrations. All 17 tables (including migration metadata)
have RLS enabled. Runtime uses Neon's pooled endpoint; migrations use its direct
endpoint. Both require verified TLS.

Keep `.env.arc-hosted` mode 0600, separate from `.env.arc-dev`. The hosted runner
accepts only explicit Neon endpoint/role/database URLs and Arc Testnet settings.
It excludes all signer, admin, weather-provider and cron secrets. Vercel receives
only runtime `DATABASE_URL`, public Thirdweb/chain/proxy configuration, `RPC_URL`,
`WEATHERB_ENV_FILE=none`, and `NEXT_TELEMETRY_DISABLED=1`. No migration URL or wallet
file goes to Vercel. `.vercelignore` excludes every `.env.*`, `.tools`, backups,
and other non-runtime files.

## Operator commands

Use Node 24.21.0 from the repository root:

```sh
npm run arc:hosted -- migrate
npm run arc:hosted -- seed
npm run arc:hosted -- reconcile
npm run arc:hosted -- check
```

`migrate` reapplies the restricted access policy after pending migrations; `seed`
is additive. `reconcile` has no signing capability and uses the shared deployment
binding and chain-to-database reconciliation. It preserves fixture flags and
terminal records. No command loads the local test-wallet keys.

Vercel cron remains absent (`vercel.json` has `crons: []`). Since September 20,
settlement runs from the dedicated worker described below, not from the local
heartbeat; the scheduler flag remains paused and scheduled creation is still a
manual owner command. Browser claims remain the user's or teammate's responsibility.

### Triggers

- QStash schedule `weatherb-arc-settle-sweep`: `*/2 * * * *` → `GET /api/cron/settle-markets`
  with the bearer secret, `retries: 0`. This sweep is authoritative: it reconciles every
  unsettled market plus any new IDs, settles or cancels what is due, and schedules
  per-market deliveries.
- Per-market QStash message: published once per market (`Market.settlementMessageId`) for
  `POST /api/markets/<id>/settle` at `resolveTime`, `retries: 3`. It is an accelerator only.
- Vercel cron is not used for either project.

### Execution semantics

- One writer per signer: each run takes the `WorkerLease` row `settler:<address>` for
  280 s (`maxDuration` is 300 s). A concurrent run returns `409 { busy: true }` and is
  logged as `busy`. A crashed run's lease expires on its own.
- Submission tracking: `Market.settlementTxHash` and `settlementSubmittedAt` are written
  before the receipt wait. On the next run an unmined hash younger than 180 s returns
  `202 in_flight` with no new transaction; older than 180 s is resubmitted (the contract
  rejects a second settlement anyway). A mined hash is reconciled from chain state.
- `settlementAttempts` / `lastSettlementError` (redacted) record every attempt.
- Provider failure inside the ten-minute window is retried on the next sweep; after the
  window the market is cancelled and every stake becomes refundable.
- Paused (`settlerPaused=true`): every trigger returns `200 { skipped: true }` and logs a
  `skipped` run — this is not a success; `worker.lastSuccessfulSweepAt` stops advancing.

### Reading the Operations page

`/admin/operations` (public site, wallet in `ADMIN_WALLETS`, read-only) shows alerts,
settler address and balance, outstanding markets (deadlines, attempts, last error,
submission hash) and the last 25 runs. `/api/health` on either origin exposes the same
`worker` summary. Alerts:

| Code | Level | Meaning / action |
|---|---|---|
| `market-overdue` | critical | Window closed, market not terminal. The next sweep cancels it; if it persists, check the worker health, QStash logs, and settler balance. |
| `worker-stale` | critical | No successful sweep in 6 min while unpaused. Run `npm run arc:worker -- check`; inspect the QStash schedule. |
| `settlement-retrying` | warning | Due market with a recorded error; normal while the provider has no observation yet. |
| `settler-paused` | warning | Markets are due while settlement is paused. |
| `worker-failed` | warning | Most recent sweep failed; read its redacted error in the runs table. |
| `settler-low-balance` | warning | Hosted settler below 0.2 USDC. Fund it: `npm run arc:lifecycle -- fund-hosted-settler`. |

Admin writes are disabled unless the public project sets `ADMIN_WRITES_ENABLED=true`
(not set). See `docs/backlog-and-ideas.md` for fine-grained permissions.

## Teammate acceptance

Open the site, connect a wallet, switch to Arc Testnet, obtain faucet test USDC,
and place a small YES or NO bet on Austin ≥78°F. Native USDC pays both stakes and
gas; keep a little balance for claims. The minimum stake is 0.01 USDC. Verify the
receipt and automatic pool refresh, then claim after settlement through My Positions.
No mainnet funds are involved.

Public HTTP and browser checks do not substitute for a teammate's successful
wallet connection and signed bet on this hosted origin. Thirdweb origin restrictions,
if enabled in that account, must allow `weatherb-arc-testnet.vercel.app`.
