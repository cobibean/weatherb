Automated · live
Settlement & cancellation

Every two minutes a hosted worker checks the chain, fetches the Austin reading, and resolves any market whose time has come. If no valid reading arrives inside the 10-minute window, it cancels and unlocks refunds. Proven three times today on real 30-minute markets.

Automated · live since 21:02 UTC
Creating the daily markets

The contract gained a scheduler role (2.3.0) so creation no longer needs the owner key. At 12:05, 13:05, 14:05, 15:05 and 16:05 UTC the worker creates one public 24-hour market for the next city in rotation. Every night at 02:30 UTC a hidden 30-minute canary market runs the whole create→settle loop so problems surface in half an hour, not a day. Duration is now declared per market on chain (2.4.0), bounded 15 min – 7 days.

Why two triggersTomorrow.io publishes the reading ~15–20 s late, so the per-market nudge usually fails once. The 2-minute sweep is the one that actually settles. Either alone would work; both together is belt-and-braces.
Why a separate projectThe public website has zero secrets. Even a bug there can't leak or use the signing key. The worker runs the same code with a different env and a locked-down database role.
Why it can't double-settleThe contract only accepts one settlement; the worker holds a per-signer lease; and it records the tx hash before waiting, so a crash mid-flight is recognised, not repeated.

04

Safety nets, in plain words

Six things that keep unattended operation boring.

1

One settler on chain

The contract accepts settlement from exactly one address. It's the worker's. Nothing else can even try.

2

One run at a time

A database lease per signer. If two runs overlap, the second says “busy” and leaves.

3

Remembers what it sent

Tx hash is saved before waiting for confirmation. If the function dies mid-flight, the next run checks that hash instead of sending again.

4

The sweep always wins

Even if QStash drops a nudge, the 2-minute sweep finds every unsettled market and handles it — including cancellation after the window.

5

Chain is the truth

The database is rebuilt from on-chain state after every action. A DB hiccup can never cause a second transaction.

6

Admin is read-only

All write buttons are disabled and their routes return 403 until a single env flag is flipped after a security review.
