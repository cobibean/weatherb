### Wednesday 8 AM: Technical Insight Thread (5 tweets)

**Tweet 1**:
```
🔧 Technical insight: UUPS proxy pattern

We chose UUPS for WeatherB because it makes sense for a brand-new product. Here's why. 🧵
```

**Tweet 2**:
```
UUPS = Upgradeable Proxy Using Universal Upgradeable Proxy Standard

What it means: We can upgrade the contract to fix bugs without changing the user-facing address.

Why it matters: Users don't have to migrate. Their funds stay in the same place.

Security win.
```

**Tweet 3**:
```
Traditional proxy patterns (Transparent, Beacon) have tradeoffs:

Transparent = admin can steal funds
Beacon = admin key is a single point of failure

UUPS = authorizes upgrades in the contract itself, not a separate admin contract.

Lower risk for users.
```

**Tweet 4**:
```
Trade-off: Slightly more gas per call (~200 wei per transaction).

For a new product where we'll iterate quickly? Worth it.

We save money on deployments. Users save money on trust assumptions.

Net positive for everyone.
```

**Tweet 5**:
```
This is why we chose MET Norway for weather data:

Accuracy at the 0.1°F resolution we need
Published in real-time
Free for non-commercial
Maintained by Norwegian meteorologists

One less risk in the system.

Technical decisions compound into product reliability.
```
